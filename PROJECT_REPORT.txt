1. EXECUTIVE SUMMARY
================================================================================

The ATS Resume Analyzer is an enterprise-grade, privacy-first software system
engineered to evaluate resume compatibility against job descriptions using
client-side Machine Learning. By executing transformer-based sentence embedding
inference directly within the candidate's browser via WebAssembly (WASM), the
application eliminates all server-side document ingestion, guarantees complete
data sovereignty, and operates with zero recurring infrastructure expenses.

1.1 Core Value Proposition
--------------------------
* Absolute Data Sovereignty: Resumes contain sensitive personally identifiable
  information (PII), employment histories, and contact records. Unlike commercial
  ATS checkers that upload user documents to centralized cloud databases, this
  system processes 100% of the text locally in the browser memory.
* Serverless Edge Distribution: Employs a Cloudflare Worker proxy to stream and
  edge-cache open-source Hugging Face model weights (Xenova/all-MiniLM-L6-v2),
  bypassing Cross-Origin Resource Sharing (CORS) boundaries while minimizing
  download latency across global geographic regions.
* Multi-Dimensional Evaluation: Synthesizes dense vector semantic similarity
  with an exhaustive 5-gram skill taxonomy engine and domain affinity heuristics,
  generating deterministic, explainable ATS scores bounded strictly between 0
  and 100.
* Interactive Candidate Remediation: Features a real-time Skill Match Map UI
  that visualizes matched qualifications alongside critical missing skills,
  supported by one-click clipboard exports for immediate resume optimization.

2.1 The Modern ATS Landscape
----------------------------
Over 98% of Fortune 500 corporations and greater than 75% of mid-market
organizations rely on automated Applicant Tracking Systems (e.g., Workday,
Taleo, Greenhouse, Lever) to filter inbound candidate resumes. Candidates face
two systemic obstacles:

1. Algorithmic Opacity: Applicants cannot easily assess whether their resumes
   align with specific job descriptions prior to formal submission, leading to
   high rejection rates caused by terminology mismatches.
2. Privacy Risks: Commercial ATS optimization tools require users to upload
   unredacted resumes to third-party cloud servers, exposing sensitive personal
   information and contact records to data collection policies.

2.2 Solution Strategy
---------------------
This system addresses both challenges through transparent, auditable, and
completely localized evaluation logic:

+----------------------------+-------------------------------------------------+

3.2 Web Workers & Comlink RPC Isolation
---------------------------------------
Running transformer embedding generation on the main browser thread causes the
UI to freeze and drop frames. The system solves this by delegating all ML
operations to a background Web Worker (src/workers/ats-worker.ts). Comlink
provides a transparent Remote Procedure Call (RPC) bridge over MessageChannel,
exposing worker methods as standard async TypeScript functions to the main thread.

3.3 Cloudflare Worker Proxy Mechanism
-------------------------------------
Direct requests from browser clients to Hugging Face CDN endpoints frequently
fail due to missing or inconsistent Access-Control-Allow-Origin headers.
The custom Cloudflare Worker (worker.js) intercepts requests directed to
/models-proxy/*, rewrites the destination to huggingface.co, appends permissive
CORS headers, and applies an edge cache directive:
Cache-Control: public, max-age=604800, immutable.

4. AI & MACHINE LEARNING PIPELINE
================================================================================

4.1 Transformer Model Specification
-----------------------------------
* Model Identifier:     Xenova/all-MiniLM-L6-v2
* Base Architecture:    DistilBERT (MiniLM 6-layer student model)
* Hidden Dimension:     384
* Transformer Layers:   6
* Attention Heads:      12
* Vocabulary Size:      30,522 WordPiece tokens
* Quantization:         8-bit Integer (ONNX dynamic quantization)
* Memory Consumption:   ~23 MB (compressed WASM weights) / ~90 MB runtime heap

4.2 Mathematical Formulation of Vector Similarity
-------------------------------------------------

Step 1: Text Tokenization and Truncation
Input strings (Resume R and Job Description J) are truncated to an upper bound
of 10,000 characters to prevent token limit overflow and quadratic self-attention
latency:
    TruncatedText = Truncate(RawText, 10000)

Step 2: Mean-Pooled Contextual Representations
Given the sequence of token representations {h_1, h_2, ..., h_L} produced by
the final transformer layer with attention mask {m_1, m_2, ..., m_L} where m_i in {0, 1}:
    u_unnorm = SUM(m_i * h_i, i=1..L) / SUM(m_i, i=1..L)

Step 3: L2 Unit Normalization
The resulting 384-dimensional vector is projected onto the unit hypersphere:
    u_norm = u_unnorm / SQRT( SUM(u_k^2, k=1..384) )

Step 4: Cosine Similarity Computation
Because both embedding vectors are normalized to unit magnitude (||u|| = 1),
cosine similarity simplifies directly to the Euclidean dot product:
    S_semantic(R, J) = u_norm_R . u_norm_J = SUM(u_R,k * u_J,k, k=1..384)
In real-world resume and job document comparisons, S_semantic falls between 0.10
and 0.95.

5. SKILL TAXONOMY & EXTRACTION ENGINE
================================================================================

While dense embeddings evaluate holistic semantic context, Applicant Tracking
Systems enforce rigorous validation of explicit technical qualifications and tools.

5.1 Taxonomy Database Construction
----------------------------------
The system maintains a comprehensive dictionary (public/skills_taxonomy.json, ~6 MB)
covering thousands of verified competencies categorized into industry domains:
* Software Engineering: Languages, frameworks, design patterns, databases.
* Cloud Infrastructure: CI/CD automation, containers, Kubernetes, IaC.
* Data Engineering & ML: Tensor computing, ETL pipelines, analytics, statistics.
* Product & Architecture: Agile methodologies, Scrum ceremonies, UX wireframing.

5.2 5-Gram Sliding Window Matching Algorithm
--------------------------------------------
To identify compound technical terms (e.g., "Continuous Integration", "Amazon
Web Services", "PostgreSQL", "React Native"), the tokenizer uses a greedy
descending n-gram window algorithm:

1. Tokenize document text into word sequences, filtering out non-word delimiters.
2. Generate all candidate phrases for lengths n in [5, 4, 3, 2, 1].
3. For each candidate phrase, perform a hash lookup against the canonical taxonomy.
4. When a match is found, assign the canonical skill representation and mark the
   constituent tokens as consumed to prevent duplicate sub-string matches.
5. Derive the intersection of resume and job skill sets:
   - Matched Skills = ResumeSkills INTERSECT JobSkills
   - Missing Skills = JobSkills EXCEPT ResumeSkills

6. SCORING FORMULATION & MATHEMATICAL DERIVATIONS
================================================================================

The final ATS score (0 to 100) is calculated via a multi-factor equation
combining semantic similarity, domain compatibility, and keyword completeness.

6.1 Step-by-Step Scoring Logic
------------------------------
1. Base Semantic Score:
   BaseScore = S_semantic * 100

2. Domain Affinity Heuristic:
   isSameDomain = (DomainSimilarity > 0.50)
   If isSameDomain AND SkillMatchFactor > 0.30:
       AdjustedScore = 50 + (BaseScore * 0.50)
   Else:
       AdjustedScore = BaseScore

3. Non-Linear Skill Gap Penalty:
   SkillMatchFactor = |MatchedSkills| / ( (|ResumeSkills| + |JobSkills|) / 2 )

   Piecewise Penalty Function:
   If SkillMatchFactor < 0.10:
       AdjustedScore = AdjustedScore * 0.50
   Else if SkillMatchFactor < 0.30:
       AdjustedScore = AdjustedScore * 0.70
   Else if SkillMatchFactor < 0.50:
       AdjustedScore = AdjustedScore * 0.85

   Additional Zero-Match Penalty:
   If |MatchedSkills| == 0:
       AdjustedScore = AdjustedScore - 20

4. Boundary Clamping:
   FinalScore = Clamp(0, 100, AdjustedScore)

6.2 Auxiliary Metric Equations
------------------------------
* Confidence Score:
  Confidence = (0.70 * S_semantic + 0.30 * |S_domain|) * 100

* Domain Compatibility Indicator:
  DomainCompatibility = Clamp(0, 100, (S_domain * 50) + 50)

* Skill Depth Metric:
  SkillDepth = Clamp(0, 100, SkillMatchFactor * 100)

7. USER INTERFACE & SKILL MATCH MAP
================================================================================

7.1 Interactive Skill Match Map
-------------------------------
The application features a responsive visual diagnostic tool integrated
directly into the analysis results view:
* Matched Skills Column: Green-highlighted badges indicating technical competencies
  verified in both the resume and the job listing.
* Missing Skills Column: Red-highlighted badges highlighting critical qualifications
  demanded by the employer that are absent from the resume.
* Overflow Protection: Caps rendered badges at 18 per category with dynamic
  "+N more" counters to maintain layout stability.
* One-Click Clipboard Actions:
  - "Copy missing skills": Copies a clean text list of identified deficiencies.
  - "Copy score card": Exports an ASCII audit summary for candidate records.

7.2 PDF Parsing Subsystem
-------------------------
Utilizes pdfjs-dist to parse incoming binary PDF documents into plain text
streams within a secondary dedicated web worker. Features a dual-path fallback:
if local worker resolution encounters security restrictions, the system
automatically transitions to CDN-hosted parsing assets (cdnjs.cloudflare.com).

8. DEPLOYMENT INFRASTRUCTURE & SECURITY
================================================================================

8.1 Cloudflare Edge Specification (wrangler.jsonc)
--------------------------------------------------
Configuration parameters:
* Service Name:        internship-project
* Compatibility Date:  2025-10-17
* Worker Script:       worker.js
* Static Assets Dir:   ./dist
* Routing Directives:  run_worker_first: ["/models-proxy/*"]

The run_worker_first routing rule ensures that model requests are captured by
the edge worker rather than falling through to static 404 asset handlers.

8.2 Security Headers & Cross-Origin Isolation (public/_headers)
---------------------------------------------------------------
* Cross-Origin-Opener-Policy: same-origin
* Cross-Origin-Embedder-Policy: credentialless

Cross-Origin Isolation is mandatory for browsers to unlock SharedArrayBuffer,
which enables multithreaded WASM execution inside ONNX Runtime. The credentialless
mode permits loading external fonts and resources without requiring explicit
Cross-Origin-Resource-Policy headers on every third-party asset.
