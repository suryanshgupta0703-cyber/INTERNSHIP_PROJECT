1. INTRODUCTION & MOTIVATION
================================================================================

1.1 What is an ATS?
When you apply for a job online (on LinkedIn, Indeed, or company portals), your
resume rarely goes directly to a human recruiter. Instead, it is first screened
by software called an Applicant Tracking System (ATS). Systems like Workday,
Taleo, Greenhouse, and Lever parse the resume text and score how closely it matches
the job description. If the score is too low or required skills are missing, the
resume is automatically filtered out.

1.2 The Two Big Problems Job Seekers Face:
1. Black Box Screening: Applicants have no way of knowing how their resume
   scores against an ATS before submitting their application.
2. Serious Privacy Risks: Commercial ATS tools (like Jobscan or Resumake) require
   users to upload their resumes to private cloud databases. Resumes contain your
   full name, phone number, home address, email, education, and career history.
   Sending this data over the internet exposes users to privacy leaks, marketing
   spam, and third-party AI training without consent.

1.3 Our Solution:
The ATS Resume Analyzer is an open-source, web-based tool that calculates a
comprehensive ATS compatibility score ENTIRELY INSIDE YOUR WEB BROWSER.
- Zero bytes of resume text leave your device.
- It uses state-of-the-art transformer AI models running locally on your CPU/GPU.
- It costs $0.00 to host and run because it does not require a costly backend
  AI server.

2. BEGINNER-FRIENDLY CONCEPT EXPLAINER
================================================================================

If you are a student or fresher new to Machine Learning and Web Development,
here is how the core concepts work in plain English:

2.1 What are "Embeddings"?
Computers do not understand the English language; they only understand numbers.
An embedding model is a specialized neural network that reads a sentence or
paragraph and turns the entire meaning into a list of 384 numbers (called a
"dense vector").
- For example: "I write Python backend services" and "Experienced in Python API
  development" will produce two lists of 384 numbers that are almost identical.
- Even though the words are different, the model understands they mean the same thing!

2.2 What is "Cosine Similarity"?
Imagine two arrows starting from the origin (0,0) in 3D space:
- If both arrows point in the exact same direction, the angle between them is 0
  degrees, and the cosine is 1.0 (100% similarity).
- If the arrows are at right angles (perpendicular), the cosine is 0.0 (unrelated).
- If they point in opposite directions, the cosine is -1.0.
By calculating the dot product between the 384 numbers of the resume and the 384
numbers of the job description, we get an instant mathematical score of how
conceptually similar they are!

2.3 What is WebAssembly (WASM)?
JavaScript is great for websites, but heavy math (like multiplying millions of
neural network weights) is too slow in standard JavaScript.
WebAssembly is a technology that allows pre-compiled, high-performance C++ code
to run directly inside your browser at near-native speed. Our AI model runs via
ONNX Runtime compiled to WebAssembly.

2.4 What is a Web Worker? (Why the browser doesn't freeze)
JavaScript in a browser runs on a single "main thread". If you run a heavy AI
calculation on the main thread, the entire webpage freezes: buttons stop clicking,
animations stutter, and the browser shows a "Page Unresponsive" popup.
To prevent this, we use a "Web Worker" — a separate background helper thread.
Think of the main thread as a restaurant waiter who smiles and takes your order,
while the Web Worker is the chef cooking in the background. The waiter never
stops serving customers while the food is being cooked!

2.5 What is CORS, and why do we need a Cloudflare Worker?
CORS stands for "Cross-Origin Resource Sharing". For security, web browsers block
websites from downloading large files from other domains (like huggingface.co)
unless that domain sends an explicit permission header.
Hugging Face often forgets to send these headers. To fix this without buying an
expensive backend server, we use a free Cloudflare Worker. The worker acts as a
lightweight proxy: it fetches the model file from Hugging Face, adds the required
CORS permission headers, and caches the file at the edge for 7 days so it loads
blazing fast.

3. END-TO-END USER JOURNEY
================================================================================

Here is the exact lifecycle of an analysis from the moment a candidate visits
the website to the moment they receive their score:

Step 1: Application Load
1. The user navigates to the deployed URL. Cloudflare Pages instantly serves
   the static files (HTML, CSS, compiled JavaScript).
2. The browser automatically registers a Service Worker (sw.js) for offline
   support.
3. In the background, a Web Worker is spawned (ats-worker.ts).
4. The Web Worker initializes Transformers.js and fetches the AI model weights
   (Xenova/all-MiniLM-L6-v2) through the Cloudflare proxy (/models-proxy/*).
5. The model weights are cached in the browser's IndexedDB / Cache storage so
   future loads take less than 1 second!
6. The UI enables the "Run AI Analysis" button once the model is ready.

Step 2: Input Ingestion
1. The user pastes their resume text OR drags and drops a PDF file.
2. The user pastes the target job description text.
3. If a PDF was uploaded, our PDF service (src/services/pdf.ts) extracts all
   text items page-by-page using PDF.js.

Step 3: Text Parsing & Cleaning
1. The raw text is passed to IntelligentTextParser (src/core/text-parser.ts).
2. Noise patterns are stripped: email addresses, phone numbers, LinkedIn URLs,
   GitHub links, and social links are removed because they do not contribute to
   job qualification scoring.
3. Sections are detected: Headings like "Experience", "Skills", "Education",
   "Summary", and "Projects" are categorized.
4. Content is prioritized: Core qualifications and skills are moved to the top
   so the most impactful text fits within the model's token limit.

Step 4: Skill Taxonomy Matching
1. The cleaned text is passed to SkillExtractor (src/core/skill-extractor.ts).
2. The extractor scans the text using a 5-gram sliding window against our curated
   taxonomy database (/skills_taxonomy.json, ~6 MB).
3. It detects both single-word skills ("Python", "Docker") and multi-word
   skills ("Continuous Integration", "Amazon Web Services").
4. It computes:
   - Matched Skills: Skills found in both the resume AND the job description.
   - Missing Skills: Skills requested by the job description but absent from
     the resume.

Step 5: Machine Learning Inference
1. The resume text and job text are passed to the transformer pipeline.
2. The model generates a 384-dimensional unit-normalized embedding for both.
3. It calculates the dot product (cosine similarity) between the two vectors.
4. It also computes a domain similarity score to check if the resume and job
   belong to the same industry.

Step 6: Hybrid Scoring & Recommendations
1. The engine combines semantic similarity, domain match, and skill gap into a
   single score (0 to 100).
2. Actionable recommendations are generated based on the score tier.
3. Results are sent back across the Comlink bridge to the main thread.

Step 7: Visual UI Presentation
1. The circular score gauge animates to the final rating (e.g., 78/100).
2. Sub-metrics are displayed: Confidence %, Domain Match %, Skill Depth %.
3. The interactive "Skill Match Map" renders green chips for matched skills
   and red chips for missing skills.
4. The user can click "Copy missing skills" to paste missing keywords directly
   into their resume draft.

6. THE AI/ML PIPELINE: Xenova/all-MiniLM-L6-v2 EXPLAINED
================================================================================

6.1 Model Architecture & Specifications
---------------------------------------
* Model Name:          Xenova/all-MiniLM-L6-v2
* Base Architecture:   DistilBERT / MiniLM (6 transformer layers)
* Parameter Count:     22.7 Million parameters (compact student model)
* Output Dimension:    384 floating-point numbers per text
* Quantization:        int8 (quantized weights, ~23 MB compressed)
* Execution Runtime:   ONNX Runtime Web running on WebAssembly (WASM)

6.2 Why this model is ideal for In-Browser ATS:
1. Compact Download: Traditional models like BERT-Base are over 400 MB, which
   would take minutes to download over mobile internet. all-MiniLM-L6-v2 is
   quantized to ~23 MB and downloads in just a few seconds.
2. Fast Inference: Sentence embedding generation takes only 200 ms to 500 ms
   on modern laptop and mobile CPUs.
3. High Semantic Accuracy: Despite its small size, it scores over 80% on standard
   semantic textual similarity (STS) benchmarks.

6.3 The 4-Step Mathematical Process:
Step 1: Text Tokenization
  The resume and job description text are tokenized into sub-word tokens using
  WordPiece tokenization. Input is capped at 10,000 characters to prevent
  memory overload.

Step 2: Transformer Layer Processing
  The tokens pass through 6 self-attention transformer layers. Each token
  produces a 384-dimensional contextual vector: h_1, h_2, ..., h_L.

Step 3: Mean Pooling
  To get a single vector representing the ENTIRE document, we compute the
  average (mean) across all token vectors, ignoring padding tokens:
      u_unnorm = SUM(m_i * h_i) / SUM(m_i)
  where m_i is the attention mask (1 for real words, 0 for padding).

Step 4: L2 Unit Normalization & Cosine Similarity
  The vector is normalized to a length of 1:
      u_norm = u_unnorm / SQRT(u_1^2 + u_2^2 + ... + u_384^2)
  Because both vectors have length 1, their cosine similarity is simply their
  dot product:
      Similarity = u_resume . u_job = SUM(u_resume[k] * u_job[k], k=1..384)
  This gives a decimal number between 0.0 and 1.0 representing conceptual alignment.

7. SKILL TAXONOMY & 5-GRAM EXTRACTION ENGINE
================================================================================

Why Semantic Similarity Alone Isn't Enough:
A resume might be semantically similar to a job posting (e.g., discussing "cloud
applications and servers"), but if the job specifically requires "Kubernetes"
and the applicant only knows "Heroku", a recruiter will reject the applicant!
Real ATS systems check for explicit keywords.

The 5-Gram Extraction Algorithm:
Our custom SkillExtractor (src/core/skill-extractor.ts) works as follows:

1. Text Tokenization:
   The text is converted to lowercase and split into words using delimiters:
   whitespace, commas, dashes, bullets, slashes, and brackets.
   Words of 1 character are ignored.

2. N-Gram Phrase Generation:
   An "n-gram" is a phrase of n consecutive words. The extractor generates all
   possible phrases of 1, 2, 3, 4, and 5 words:
   - 1-gram: "python", "docker", "cloud"
   - 2-gram: "machine learning", "react native", "spring boot"
   - 3-gram: "amazon web services", "continuous integration pipeline"
   - 4-gram: "natural language processing pipeline"

3. Greedy Descending Match:
   The algorithm sorts all candidate phrases by length in descending order
   (longest phrases checked first). This guarantees that specific multi-word
   skills (like "Amazon Web Services") are matched as a complete skill rather
   than matching "Amazon" and "Web" as unrelated single words.

4. Canonical Lookup:
   Each phrase is checked against our taxonomy hash map (/skills_taxonomy.json).
   Synonyms and variations are mapped to a single standard name:
   - "k8s"       --> "Kubernetes"
   - "postgres"  --> "PostgreSQL"
   - "react.js"  --> "React"
   - "vuejs"     --> "Vue.js"

5. Set Arithmetic:
   - Matched Skills = ResumeSkills INTERSECT JobSkills
   - Missing Skills = JobSkills EXCEPT ResumeSkills

8. THE SCORING FORMULA & STEP-BY-STEP CALCULATION WALKTHROUGH
================================================================================

8.1 The Exact Formula Used in Code (ats-engine.ts: lines 380-447)
----------------------------------------------------------------

1. Base Semantic Score:
   baseScore = semanticSimilarity * 100

2. Skill Match Factor:
   averageSkills = (resumeSkillsCount + jobSkillsCount) / 2
   skillMatchFactor = matchedSkillsCount / averageSkills

3. Domain Affinity Boost:
   isSameDomain = domainSimilarity > 0.50
   If (isSameDomain == true AND skillMatchFactor > 0.30):
       score = 50 + (baseScore * 0.50)
   Else:
       score = baseScore

4. Non-Linear Skill Gap Penalties:
   If skillMatchFactor < 0.10:       // Very poor skill alignment
       score = score * 0.50          // Deduct 50%
   Else if skillMatchFactor < 0.30:  // Weak skill alignment
       score = score * 0.70          // Deduct 30%
   Else if skillMatchFactor < 0.50:  // Moderate skill alignment
       score = score * 0.85          // Deduct 15%
   Else:
       // Good skill alignment (>= 0.50): no penalty!

5. Zero Matched Skills Penalty:
   If matchedSkillsCount == 0:
       score = score - 20            // Direct 20-point deduction

6. Boundary Clamping:
   FinalScore = Clamp(0, 100, score)

7. Auxiliary Metrics:
   - Confidence = (semanticSimilarity * 0.70 + |domainSimilarity| * 0.30) * 100
   - Domain Compatibility = Clamp(0, 100, domainSimilarity * 50 + 50)
   - Skill Depth = Clamp(0, 100, skillMatchFactor * 100)


8.2 A Practical Numerical Walkthrough (Fresher Example)
-------------------------------------------------------
Let's calculate a score by hand to see how simple it is!

Scenario:
- An applicant applies for a Junior Backend Developer job.
- Semantic Similarity = 0.75 (meaning 75% semantic match)
- Domain Similarity   = 0.60 (both are in Software Engineering)
- Resume Skills Found: 8 skills (Python, Django, Git, SQL, HTML, CSS, Linux, REST)
- Job Skills Found:   12 skills (Python, Django, Docker, Kubernetes, AWS, SQL, Redis, Git, CI/CD, Celery, TDD, Agile)
- Matched Skills:      4 skills (Python, Django, SQL, Git)

Step 1: Calculate Base Score
  baseScore = 0.75 * 100 = 75.0

Step 2: Calculate Skill Match Factor
  averageSkills = (8 + 12) / 2 = 10
  skillMatchFactor = 4 / 10 = 0.40

Step 3: Check Domain Boost
  isSameDomain is true (0.60 > 0.50)
  skillMatchFactor is 0.40 (which is > 0.30)
  Therefore, domain boost triggers!
  score = 50 + (75.0 * 0.50) = 50 + 37.5 = 87.5

Step 4: Check Skill Gap Penalty
  skillMatchFactor is 0.40 (falls in the 0.30 <= factor < 0.50 bracket)
  score = 87.5 * 0.85 = 74.375

Step 5: Check Zero Matched Skills Penalty
  matchedSkillsCount is 4 (not 0), so no extra deduction.

Step 6: Clamp Final Score
  Final Score = 74.4 / 100

Step 7: Calculate Auxiliary Metrics
  - Skill Depth = 0.40 * 100 = 40%
  - Confidence  = (0.75 * 0.70 + 0.60 * 0.30) * 100 = (0.525 + 0.180) * 100 = 70.5%
  - Domain Compatibility = (0.60 * 50) + 50 = 80%

Result: The candidate receives a solid, explainable score of 74.4 with clear
guidance to learn the 8 missing skills (Docker, Kubernetes, AWS, etc.)!

9. CLOUDFLARE EDGE PROXY & CORS ARCHITECTURE (worker.js)
================================================================================

Why is worker.js essential?
In modern web browsers, security policies prevent frontend JavaScript from
fetching assets from third-party websites unless the server returns permissive
CORS headers (Access-Control-Allow-Origin: *).
Hugging Face's file servers frequently return responses without these headers
when accessed from Cloudflare Pages domains. Without a proxy, the browser throws:
"TypeError: Failed to fetch (CORS header missing)".

How our Cloudflare Worker solves this (worker.js):
1. Route Interception:
   Any request starting with /models-proxy/* is intercepted by worker.js before
   it reaches static asset hosting (configured via run_worker_first in wrangler.jsonc).
2. Path Rewriting:
   The worker strips "/models-proxy/" from the URL and constructs the target:
   https://huggingface.co/{model_path}
3. Upstream Streaming Fetch:
   The worker fetches the binary model weights from Hugging Face.
4. CORS & Cache Injection:
   The worker appends:
   - Access-Control-Allow-Origin: *
   - Access-Control-Allow-Methods: GET, HEAD, OPTIONS
   - Cache-Control: public, max-age=604800, immutable
5. Fast Edge Response:
   The response is cached in Cloudflare's worldwide CDN cache for 7 days.
   Returning visitors download model files directly from nearby Cloudflare data
   centers in milliseconds!

11. SECURITY, PRIVACY & BROWSER ISOLATION
================================================================================

11.1 Complete Privacy Architecture
* Zero Server Ingestion: Resumes and job descriptions are processed solely
  within browser memory. No backend database exists.
* Zero Telemetry: No tracking pixels, Google Analytics, or third-party cookies.
* Strict Content Truncation: Prevents Denial-of-Service attacks by capping text
  processing at 10,000 characters and file uploads at 10 MB.
* XSS Prevention: All dynamic text rendered into HTML chips passes through an
  HTML escaping function (escapeHtml) in src/ui/analysis.ts.

11.2 Why public/_headers has COEP: credentialless
* Multithreaded WebAssembly in ONNX Runtime requires SharedArrayBuffer.
* Web browsers mandate Cross-Origin Isolation before enabling SharedArrayBuffer:
  - Cross-Origin-Opener-Policy: same-origin
  - Cross-Origin-Embedder-Policy: credentialless
* Why credentialless? Traditional require-corp breaks external font downloads
  (like Google Fonts) that lack Cross-Origin-Resource-Policy headers.
  credentialless unlocks SharedArrayBuffer while allowing external fonts and
  CDN assets to load without errors.
